## 2026-09-17 チルトシフトとビネット

- ユーザー採用値：ぼかし3px（基準幅342px）、位置50%、くっきり残す幅70%、移行幅50%。ダンジョンのビネットは暗さ90%、明るい範囲15%。`FEEL_TUNING` の `tilt*` / `vignette*` に集約。

- スマホ試遊版：既存の本人限定Siteの `/play/index.html` に本編を配置。

## 編集先

- `proto/game-feel.js`：揺れ、歩行アニメーション、被弾点滅、照明、環境装飾、水面、粒子、攻撃の軌跡、ドロップとボス撃破演出。
- `proto/index.html`：既存のダメージ式、経験値・報酬の計算、AI、移動・弾の当たり判定。描画内の `feel*` / `drawFeel*` 呼び出しが演出との接点。
- `proto/feeltest.html`：ブラウザで開く演出・接続の回帰検証。

HTML末尾で `game-feel.js` を読み込む。外部ファイルは `update` / `killEnemy` の元処理を保持してラップし、`drawSwing` / `drawShot` の見た目を差し替える。元の関数名は維持する。これらの関数を改名・モジュール化する場合は接続確認が必要。
以前の未追跡 `feel.js` / `alpha.js` は現在の本体から読み込まない。今回の編集先は `game-feel.js`。

開発中は分離したまま維持し、出荷時にインライン化して「index.html単体・外部依存ゼロ」を満たす。
古いインライン版の `const FEEL` を残すと二重宣言で起動できないため、外部読み込みと併存させない。

本体を書き戻す際は、読み込みに加えて以下の接続を維持し、`proto/feeltest.html` をブラウザで実行する。

- 被弾：`hitEnemy` / `hitAlly` / `hitPlayer` の `feelImpact` と、キャラ描画の `feelBlink` / `drawFeelFlash`。
- 成功演出：`hitPlayer` の `feelJustDodge` / `feelPerfect`、主人公・仲間の大技の `feelUltimate`。
- 描画：仲間の `feelEntityOffset`、床の `feelDecorAt`、弾の `drawFeelMagic`、成功・大技・撃破リングの `drawFeelRing`。
- 環境：`drawFeelRipples` / `drawFeelMotes` / `drawFeelVignette`。ブラー粒子の `drawFeelAmbient` は本体側で石・水・木・遺跡・炉の層だけに限定する。
- ドロップ：描画の `feelDropOffset` と `autoPickup` の0.42秒待ち。SPの直接加算は元の撃破処理に維持する。

## 今回、依頼により戦闘と接続した部分

- 通常ダッシュ開始から **0.12秒**以内に着弾した攻撃を1回無効化。`hitPlayer` のダメージ・状態異常・装備摩耗より前で判定する。地形や継続ダメージには適用しない。
- ジャスト回避／パリイ成功時は **0.18秒間、0.22倍速**。全キャラと弾を同じ時間倍率で進める。探索の経過時間は実時間を保つ。
- 被弾時は描画だけを通常 **0.09マス**、ボス **0.035マス**ずらし、**0.2秒**で滑らかに戻す。連続被弾でも加算せず、実座標・当たり判定・追従距離には影響しない。既存の押し出し攻撃（`e.push`）だけは従来どおり実座標を動かす。
- ドロップは着地するまで **0.42秒**自動回収を待つ。報酬量・抽選は元の `killEnemy` が決める。
- ボス撃破は **1.15秒**の演出中だけシミュレーションを止め、終了後に報酬・クリア画面へ進む。報酬確定処理は一度だけ行う。

演出の調整値はファイル先頭の `FEEL_TUNING`。回避受付時間などは戦闘バランスにも影響するため、Claude側でもここを参照する。
装飾乱数は座標・階層から計算し、戦闘／ドロップ乱数を消費しない。歩行粒子・波紋には上限を設ける。低速移動では揺れの振幅と頻度を下げ、OSのモーション軽減設定にも従う。

## アイテムのドット絵（第一弾）

- 正本は `pixel-art/pixel-art/abyss-item-icons-export/16px-runtime/*.png` の透過PNG 20種。すべて16×16で、ファイル名を `ITEM_ART.key` のキーとして扱う。`proto/item-icons-imported-data.js` はこれらを同期ロードできるパレット・インデックス形式へ変換した実装用データ。`proto/item-icons.js` の手続き描画はデータがない場合のフォールバックとして残す。
- `proto/assets/item-icons/*.png` は正本と同じ16×16透過PNGの実装確認用書き出し。見比べ用は `proto/item-icons-preview.html`。
- `game-feel.js` の `drawFeelItemIcon` を床ドロップの装備・消耗品から呼ぶ。実環境では正本の16×16をキャラと同じ論理グリッド・同じ `TS` 幅へ平滑化なしで描画する。浮遊・着地は従来の処理を使う。光輪は装備・消耗品・SPすべて撤去。コモン（rar=0）はPNG本体の黒輪郭固定。他の装備はPNGの不透明境界上にレア度色の1ドット線を重ねる。`ITEM_ART.draw` の `outlineAlpha` で色線だけの透明度を指定できる。`FEEL_TUNING.itemOutlinePeriod=1.8` 秒、`itemOutlineMinAlpha=.25` でゆっくり明滅。周期を0にすると固定表示、OSのモーション軽減設定でも固定表示。
- 剣・大剣・短剣はそれぞれ専用アートへ対応。大剣は独立した鍔を持たない長く幅広い一枚刃、短剣は刃をさらに1ステップ短縮した細い刃。消耗品は深緑の薬=draughtを試験管、浄めの香=antidoteを葉、それ以外を丸い薬瓶へ対応。革鎧と鎖帷子はそれぞれ専用画像。円盾は小盾の絵を共用し、残りは各base名の専用アート。斧とメイスは柄をさらに2ステップ短縮。未鑑定品と専用アートが未作成の装備は袋。SPの六角形、一覧・名前の絵文字は今回の置換対象外。
- 鑑定状態・抽選・回復量などの仕様変更なし。専用アートを追加する場合は `ITEM_ART.key` の対応を増やす。
- 検証：4種類のゲーム内描画、未鑑定の袋、Canvas状態復元を確認。`feeltest.html` は変更前後で同じ7項目（回避6項目・ログ配置1項目）が失敗し、新規失敗・実行時エラーはなし。

- 指定PNGへの全差し替え：`pixel-art/pixel-art/abyss-item-icons-export/16px-runtime` の20ファイルを実ゲームへそのまま採用。可視ピクセルとアルファマスクが書き出し・実装データ間で20/20一致すること、全装備・消耗品のキー対応、コモン本体とレア度境界レイヤー、実ゲーム起動時の描画エラーなしを確認。
- レアリティ輪郭：装備の不透明領域の上下左右に透明画素が接するセルだけを1ドットの輪郭マスクとする。Commonは黒 `#171323`、Uncommonは緑 `#6cc24a`、Rareは青 `#5b8dd6`、Uniqueは紫 `#a97fe0`、Relicは赤 `#c4433f`、Legendは金 `#e8c95a`。実ゲームは同じ判定で本体輪郭上へ重ね、書き出しは `pixel-art/pixel-art/abyss-item-icons-export/rarity-outlines` に20種×6段階の透過PNGを置く。消耗品はレアリティを持たないため黒輪郭の本体を表示する。

## 採用済み戦闘エフェクトの実機接続

- 通常攻撃は `ally-effect-study.js` の武器別描画を `game-feel.js` の `drawSwing` / `drawShot` から呼ぶ。対応は剣・斧、槍、弓、短剣、戦鎚、大剣、杖魔弾。実ダメージ属性を渡し、攻撃軌跡と敵味方のヒットへ火・雷・冷気・魔法の識別演出を重ねる。
- 武器技24種は `weapon-art-effect-study.js` の `renderEffect` を正本とし、`fireArt` から `feelWeaponArtStart` へ発動位置・向き・範囲を渡す。旧 `ultring` / `lwave` / `ultline` / `ultbeam` は判定時計だけ残して描画を止め、専用演出との二重表示を避ける。
- フレイム、ライトニング、ダンシングソード、アローレインは `W.arts` の持続時間と同じ時計で描く。フレイムは8方向のV44スプライト、地走りはV30、レイジングアッパーはV18を使用する。画像は整数座標・平滑化なしで描画する。
- 居合は踏み込み中に本体を一度消して復帰させ、ミラージュは持続中の本体透明度を下げる。癒し打ちは黄緑の十字回復、属性技の着弾は通常の属性ヒット経路を通す。ダメージ倍率、範囲、リキャスト、状態異常確率は変更しない。
- 回帰検証は `feeltest.html` で、24種のモジュール描画、24種すべての実 `fireArt` 発動、持続技の重複防止、本体フェード、Canvas状態復元を確認する。既知の7失敗以外に新規失敗・実行時エラーがないことを通過条件とする。
