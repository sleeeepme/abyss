## 素材の制作と配置

内蔵image_genを使って、床テクスチャ・奥壁／手前壁アトラス・左右壁アトラスの3画像を生成。生成画像からマップ用素材を分割し、既存コンセプト系の48色パレットへ対応付けた。コンセプト画像をそのまま矩形で切り出したものではない。

保存先：`proto/assets/stone-map-study-v3/`。

| 素材 | 寸法 | 配置 |
|---|---|---|
| floor.png | 256×256 | 床。部分画像を重ね、色差の少ない画素経路で接続する。左右反転の反復による対称模様を避ける |
| north-a.png / north-b.png | 384×107 / 384×101 | 奥側の連続した岩壁。床との接点を下端として配置 |
| west.png / east.png | 60×204 / 71×204 | 左右専用の岩壁。奥壁を回転流用しない |
| south.png | 384×48 | 手前の切断面。色を暗くして床面との区別をつける |
| low-ledge.png | 384×59 | 低い岩棚。追加配置用の素材として保存。現プレビューでは未使用 |
| parts.json / parts.js | — | 寸法・切り出し範囲・パレット |

背景の暗色を透明へ変換。左右壁と手前壁は接地側の余白を詰め、浮いて見えないように合わせた。
壁の内部は暗色のまま、奥壁の背後だけ控えめな青い霞を追加。霞も通行不能領域内に制限している。
床の端には短い接地影を置く。影は床の色を変えるだけで、通行可能領域を減らさない。

パーツ縮小と描画拡大はニアレストネイバー。最終PNGは480×300の等倍と1920×1200の4倍。床・壁の描画レイヤーで使われた色は39色。これは元画像の厳密な作者パレットを特定したという意味ではなく、既存の48色パレットから使用された色数。

## 実装と検証

- `proto/stone-map-terrain-v3.js`：素材の読み込み、床の接続、方向別の壁、接地影。
- `proto/stone-map-v3.js`：V2と同じ移動・カメラ・マップ選択。
- `output/stone-map-study-v3/build-assets.cjs`：生成済み画像から素材PNGへ変換。
- `output/stone-map-study-v3/verify-export.cjs`：動作・画素検証とPNG出力。
- `output/stone-map-study-v3/verification.json`：検証結果。

本編由来seed 7 / 31 / 101と広間サンプルで確認。セル配列不変、床への壁の被り0、床の描画欠落0、半透明の輪郭画素0。
本編由来の3マップは広間から出口まで到達し、1,204回の壁へ向かう移動ですべて床側に停止。広間サンプルも別に80回確認。
4倍PNGの全4×4画素ブロックが同色であることを検証。ブラウザ実行エラーなし。

`example-floor.png`、`example-walls.png`、`example-depth.png`、`example-collision.png`、`example-map.json` にseed 7全域のレイヤーとセルデータを出力。暗色下地 → depth → floor → walls → キャラクターの順に同じ原点で描く。

本編とは分離した実装確認用プレビュー。実際の戦闘・敵味方スプライトとの見え方、端末負荷は未統合。人物は歩行確認用の仮絵。
短い壁や薄い壁では通行領域を優先して画像を切り詰めるため、角のつながりを専用素材へ置き換える余地はある。
