# 石の層：パーツ分割と既存マップ適合検証

2026-09-10。起点は `output/art-style-20260908-01a07ef8/33-stone-warm-restart-171x300-4x.png`。暖色の岩・青い奥行きの稿を配置用素材へ展開した試作。決定稿ではなく、ゲーム本体には接続していない。

## 結論

現在の正方形グリッドを維持したまま、斜め上から描いた素材で奥行きを出せる。ただしコンセプトの高い岩をそのまま各壁マスへ置くと、2マス通路を視覚的に塞ぐ。今回の推奨表示は、壁画像を論理上の壁領域でクリップする断面表示。床・階段の領域へ岩がはみ出さず、既存の移動座標・通行幅・当たり判定が一致する。

菱形のアイソメトリック投影ではない。マップ座標から画面座標への変換は本編と同じ `sx=x*TS-camX, sy=y*TS-camY`。画角の表現は素材の上面・前面による。真のアイソメトリック投影やY軸圧縮を入れる場合は、入力座標、カメラ、攻撃範囲、キャラクターの位置、UIアンカーも変換する別作業になる。

## 素材と配置データ

`proto/assets/stone-map-study-v1/` に保存。

| パーツID | 用途 |
|---|---|
| floor-0〜3 | 16px床。タイル端の色を合わせる |
| ledge | 横の岩棚・低い壁 |
| wall-tall | 高い岩塊。通行領域で切り下げる |
| corner | 角の岩塊 |
| boulder | 単独の岩 |
| spike / spikes | 石筍単体・群 |
| rubble | 小石のまとまり |
| stairs | 段差・階段 |
| moss / moss-stones | 床に重ねる苔 |
| vine | 垂れる蔦 |
| slab | 床に重ねる石板 |

床以外は48×48の透過PNG。元コンセプトの矩形切り抜きではなく、同じ絵を参照してパーツ専用のアトラスを生成し分割。生成画像に焼き付いた明るい無彩色の市松を除去して二値アルファ化し、セル境界の微小な残骸を除去。パレットは暖色系の16-final-reference-paletteを使用。追加の床4種は低密度のコード生成素材。

`parts.json` に素材寸法、下端基準アンカー、描画レイヤー、衝突用途を記録。`map.json` は手配置の床・当たり判定・パーツ位置。`floorCells` は岩の下にも床を敷くための見た目用、`cells` が通行判定。`live-maps.json` は本編の壁・床・階段を無変更で保存した3マップ。`data.js` と `live-maps.js` はfile://プレビュー用の同内容。

## 検証結果

`output/stone-map-study-v1/live-map-verification.json` と `verification.json` が証跡。

- 本編の `genFloor` を実際に呼び、深さ1・3・7・9・10 × 5seedの25通りを検証。全通行可能マスが開始地点から到達可能、階段にも到達可能。
- 本編の `moveEnt` を使い半径0.3マスで経路を実走。25通りすべて出口まで到達。
- 3seedの狭い通路付近で、壁描画あり／なしの画素を比較。断面表示では床マス内部（境界1pxを除く）への岩の被りは0。無対策配置では同じ領域に多数の被りを確認。表示モードを変えてもマップ配列は不変。
- 検証画面の移動は本編moveEntの半径・軸別判定に合わせた。壁に向かう402ケースで壁抜けなし。
- ブラウザ読み込みエラーなし。入口から出口への経路探索、マーカー操作、カメラ追従を確認。

## 本編接続時の条件・残る作業

1. 本編の `f.g`・solid・tileWalk・moveEnt・敵AI・ハザードの意味は変更せず、描画だけ差し替える。
2. 床 → 床装飾 → 壁の断面描画 → ハザード／キャラクター／戦闘演出、という接続位置を整理する。本編は地形ループのあとにハザードとキャラクターを描く。プロップを床に置く場合は、足元のYを基準にキャラクターとの前後関係を扱う必要がある。
3. 縦横や角で自然につながる壁の専用バリエーションはまだ不足。現在は岩塊の再利用＋クリップで通行領域を優先しているため、境界が直線的になり、繰り返しも見える。今回の検証は仕組みの成立確認であり、完成マップの美術品質の承認ではない。
4. 大きな石筍を通行可能床に装飾として置く場合、見た目だけの障害物にしない。通行不能セルに置くか、別途ユーザーの承認を得て配置仕様を決める。
5. 実際の敵・味方・攻撃予告・暗幕・視界・タッチ操作・実機負荷との統合検証は未実施。現在のプレビューのマーカーはキャラクター絵の代用品。
6. 出荷時の単一HTML方針に合わせ、採用素材を本編へ埋め込む。今回のプレビューは外部PNG参照。
