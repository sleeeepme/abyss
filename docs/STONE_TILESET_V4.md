# 石の層 V4：固定タイルセットと組み立てマップ

## 確認先

- `proto/stone-tileset-v4.html`：タイルシートと、そのシートから作ったマップを同じ画面で確認。
- `proto/assets/stone-tileset-v4/tiles.png`：32×32px、16列、186枚の地形タイル。
- `proto/assets/stone-tileset-v4/props.png`：64×64px、4列、12点の装飾パーツ。
- `output/stone-tileset-v4/connections.png`：広間、L字、凹み、分岐、中抜き、細い壁などの接続見本。
- `output/stone-tileset-v4/map-0-4x.png`：組み立てサンプル。

V3の大きな画像の切り抜き・描画時の合成方式から、固定タイルシートとタイルIDの配置へ変更。実行時は32pxタイルを等倍で描画し、地形の境界に合わせた画像の変形や切り抜きは行わない。

## セットの構成

| 種類 | 枚数 | 接続方法 |
|---|---:|---|
| 床 | 32 | 8列×4行のまとまりとして連続する石板模様。上下左右に反復可能 |
| 壁 | 47 | 上下左右・斜めの隣接状態から選択。直線、角、凹角、端、分岐、孤立壁など |
| 壁の差分 | 12 | 主な直線4方向×3差分。接続端を維持して岩肌を変える |
| 苔 | 47 | 同種の隣接マスに応じた塗りと境界 |
| 水面 | 47 | 同種の隣接マスに応じた岸・水面 |
| 階段 | 1 | 床セルの出口表示 |
| 装飾 | 別シート12点 | 岩・石筍・蔦・苔など。基本タイルの整数倍で配置 |

床は32枚をどの順番でも自由に混ぜられる仕様ではない。`macro`で指定した8×4の位置関係で接続する。現コンパイラーは `x % 8, y % 4` で床タイルを選ぶ。任意の形の部屋や通路をこの連続した模様で埋められるが、同じ模様の反復は残る。

壁・苔・水面の47形状は、8方向のビットマスクを正規化したもの。斜め方向は両側の直交方向がつながる場合だけ有効。`tiles.json`に形状とIDの対応を保存している。
プレビューの壁は1セル内に収まる断面表示。壁の内部は暗色。装飾の岩は2×2セルすべてが通行不能の場所に置き、床を覆わないようにしている。

## 美術素材

既存の暖色の石層コンセプトを参照し、内蔵image_genで床・岩壁・岩の上面・暗い側面の素材シートを生成。そこから接続形状を固定したタイルへ加工した。
床の連続模様と装飾には、同じコンセプトから以前に生成・透過化した素材も使用。CraftPixの画像や販売素材を切り抜いて使用したものではない。

生成原稿：`output/stone-tileset-v4/material-generated.png`。
生成指示：`output/stone-tileset-v4/PROMPT.md`。
PNGの拡縮にはニアレストネイバーを使用。タイルの輪郭に半透明のぼかしは入れない。

## マップ・Tiled用データ

`proto/assets/stone-tileset-v4/` の以下を同じフォルダーに置く。

- `stone.tsj`：地形タイルセット定義。
- `props.tsj`：装飾用タイルセット定義。
- `map-0.tmj`：組み立てサンプル。
- `map-1.tmj`〜`map-3.tmj`：本編由来seed 7 / 31 / 101。
- `map-4.tmj`：独立した接続試験図。部屋同士の歩行接続は目的としていない。
- `maps.json`：タイルID配列、元のセル配列、装飾配置。JSON内の空タイルは-1。
- `.tmj`内の空タイルは0、地形タイルのGIDはID+1。装飾のfirstgidは187。

マップは地形・壁・苔／水面・装飾に分離。水面は浅い水溜まりとして床上に描画し、通行不能にはしていない。既存の戦闘仕様や地形生成は変更しない。

## 検証

`output/stone-tileset-v4/verification.json`に記録。

- 床32枚から元の連続模様を再構成し、画素差0。反復端の画素差0。
- 壁の正規化マスク47種類を用意。
- サンプルと本編由来3マップで不正なタイルID0、床／壁と元セルの対応不一致0。
- 装飾の2×2セル領域に通行可能セルが混入していないことを確認。
- 4マップで出口への移動に成功。壁へ向かう1,324ケースですべて床側に停止。
- 地形シートの中間アルファ値0、ブラウザ実行エラー0。
- 広間、細い通路、接続試験図を画像で確認。

本編への接続は未実施。独立したプレビューで、実際の戦闘キャラクター・予告・視界処理との統合はこの成果物には含めない。
岩の反復や苔・水面の輪郭は、タイルの接続規則を維持したまま個々のPNGを磨ける構成になっている。

## 再生成

`output/stone-tileset-v4/build.cjs` → `compile-maps.cjs` → `verify.cjs` の順。
Node.js、sharp、Playwrightを利用。ビルド用スクリプトには今回の作業環境の絶対パスがある。
表示用HTML・JSは同梱フォルダー内の相対パスだけで動作する。
