## リファレンスから読み取ったこと

対象：ユーザー添付 `201E4578-5423-4ECA-A5D6-8595535130D0/1-貼り付けた画像-1.jpg`。

| 領域 | 画像で確認できる特徴 | 今回の構成 |
|---|---|---|
| 床 | 中央の人物と敵が立つ黄土色の連続面。色斑・石板・細いひびがあるが、色の境界そのものは障害物になっていない | 床マスク全体に連続した地色を敷き、複数マスにまたがる色面を重ねる。石板・小石は平たい装飾 |
| 奥側の壁 | 画像上側、床との接点から上へ立ち上がる暗い岩面。足元に石が集まり、上部は大きい暗部へ溶ける | 床の北側が壁の場合に、北へ高さを持つ壁面を生成。連続する辺をまとめ、1セル1岩の反復を避ける |
| 左右の壁 | 床の横には細い側面が見え、奥壁ほど明るい正面を見せない | 西・東で明度の異なる薄い側面。両側に高い岩を並べない |
| 手前の壁 | 画像下側に暗い上端・切断面が重なって床を囲む。奥壁と同じ明るい岩面ではない | 南側は暗い短い切断面。床の上へせり出す高さを付けない |
| 壁の内部 | 床から離れると情報が少ない大きな暗い塊になる | 暗色 `#211f24`。内部を岩の模様で埋めない |
| 陰影 | 壁の足元や割れ目に暗さが集まり、すべての物体を同じ線で囲っていない | 割れ目と接地影に線を限定し、細かい連続ハイライトを避ける |

これはスクリーンショットの見え方の分析。元ゲームの衝突データや実際のタイルアトラスを取得したものではない。
元のタイル寸法、カメラの角度、オートタイル規則は画像だけでは断定できない。今回の24pxセルは実装上の選択であり、リファレンスの寸法の推定値ではない。

画角は、床の上面と奥壁の前面が見える斜め上の見え方。これを正方形の移動座標のまま表現する。菱形の投影や座標軸の回転は行わない。

## 接続・タイリングの実装

1. 本編由来のセル配列で、FLOOR / STAIR を床、WALL を壁としてマスクを生成。
2. 床は世界座標に固定した広い色面で塗る。24pxごとに模様をリセットしないため、床タイルの格子を見せない。
3. 各床セルの上下左右を調べ、壁との境界だけを抽出。北辺・東辺・南辺・西辺を別の描画関数に送る。
4. 北辺は同じ行の連続区間をまとめて壁面にする。その中に幅の違う割れ目や石の塊を配置。左右と手前には別の輪郭を使う。
5. 角では複数の方向の壁面を接続する。最終的な壁画像を通行不能マスクで切り、隣の細い通路を覆わないようにする。
6. 描画順は暗い壁内部 → 床・平たい床装飾 → 壁面 → 歩行確認用人物。

壁の境界を作ることが主で、岩スプライトを敷き詰めることはしない。画像は整数画素のポリゴン・線で描画し、アンチエイリアスを使わない。

PNGはリファレンスからの切り抜きではなく、今回の描画コードから出力したパーツ。
`floor-macro.png` はシームレス素材ではないので単純反復しない。実装は世界座標で床模様を作る `floorTexture`、連続した壁の区間を生成する `wallRun` を使う。

描画ロジック：`proto/stone-map-terrain-v2.js`。
操作・カメラ・既存セルデータへの接続：`proto/stone-map-v2.js`。
PNGを使用して移植する場合は、サンプルの床・壁を同じ原点で重ねるか、描画関数を地形チャンク単位の生成へ移植する。24pxのセルを本編の表示サイズへ合わせる際はニアレストネイバーを使用する。

## 本編へ接続する前に残ること

今回の人物は歩行確認用の仮絵。本編の敵・味方・攻撃予告・遮蔽・視界・タッチ入力と組み合わせた確認は未実施。
地形描画はマップ切り替え時に全域を事前生成する試作。最終実装では本編のマップ寸法・端末負荷に合わせてキャッシュ単位を決める。
リファレンスの岩壁の細かな造形・照明まで完全一致したとは扱わず、床と壁が成立する構造を今回の確認対象とする。
