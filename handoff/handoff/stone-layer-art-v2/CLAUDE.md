# Claude implementation brief: 石の層アート v2

このフォルダは、Abyss の「石の層」を `proto/index.html` に実装するための引き継ぎ資料です。

## 最優先ルール

- 正本は `proto/index.html` と `docs/GAME_DESIGN.md`。
- `unity/` は凍結中。ユーザーから明示指示がない限り変更しない。
- `reference/stone-layer-sprite-sheet-v2.png` は完成済みの透過スプライトではなく、見た目と部品構成のリファレンス。
- 背景込みのシート画像を、そのままゲーム画面へ貼らない。
- 既存ゲームロジック、当たり判定、BSP生成、戦闘バランスは変更しない。

## 実装対象

`proto/index.html` の石の層（最初の10階層）の描画だけを更新する。

1. 壁
   - 石の幅・高さ・前後位置を座標ハッシュで変える。
   - 上端と外周をガタガタにし、直線的なレンガ列を避ける。
   - 同じ座標とシードなら必ず同じ形にする。
   - 石面はフラットな紫。明るいベベル、光沢、太いハイライトは禁止。
   - 当たり判定上の壁セルは変えず、描画だけをセル外へ数px張り出させる。

2. 床装飾
   - 人骨：頭蓋骨、肋骨、散らばった長骨、部分的な骸骨。
   - 蜘蛛の巣：壁の内角または壁際だけに置く。
   - 草・苔：壁際と亀裂周辺を優先し、中央には密集させない。
   - 水たまり：小・中・大を最低3形状、できれば5形状。暗い青緑で非発光。
   - 燭台：低い石台＋橙色の炎。部屋内に疎らに置き、画面を明るくしすぎない。

3. 出現制約
   - 鉱石、金、結晶、採掘道具、トロッコ、宝箱は石の層に置かない。
   - 装飾は歩行や戦闘を妨げない純粋な描画要素とする。
   - 階段、敵、プレイヤー、ドロップの視認性を優先する。
   - 階段とその周囲1セル、開始地点とその周囲1セルには大きな装飾を置かない。

## 推奨実装方法

- 既存の `drawDeco` と壁描画の近傍へ、小さなCanvas描画関数を追加する。
- ピクセルアートは整数座標・整数サイズのみ。`imageSmoothingEnabled = false` を維持する。
- `x`, `y`, フロアシードから整数ハッシュを作り、壁形状と装飾バリエーションを選ぶ。
- 水たまりは複数の矩形を組み合わせた非対称シルエットにし、反射は1〜3px程度に抑える。
- 燭台の炎は2〜3フレームでよい。決定論が必要な配置と、時間で変化する炎形状を分離する。
- 新しい外部依存や画像ローダーを追加しない。既存の単一HTML構成を維持する。

## ビジュアル基準

- `reference/concept-art.png`: 世界観、密度、壁の不揃いさの基準。
- `reference/stone-layer-sprite-sheet-v2.png`: 部品の形、色、バリエーションの基準。
- `reference/stone-layer-map-sample-v2.png`: マップに置いたときの密度と読みやすさの基準。

## 完了条件

- 石の層を複数回生成しても壁が定規で引いたような直線に見えない。
- 水たまりが最低3種類、燭台が最低1種類表示される。
- 人骨、蜘蛛の巣、草、苔が石の層にだけ適度に現れる。
- 禁止物が石の層に出ない。
- 同じシードでは装飾配置と壁形状が再現される。
- プレイヤー移動、壁判定、階段、敵、戦闘に回帰がない。
- `node proto/verify.mjs` と関連する既存テストを実行し、失敗が増えていない。
